# 코딩 작업의 완료 근거

요청한 기능이 실행되는지, 대표 입력과 실패 입력에서 어떤 결과가 나오는지 확인할 기준을 계약에 넣습니다. 구현·테스트 파일과 의존성 명세를 source_paths에 포함합니다. 기존 프로젝트의 실제 검사 명령을 재사용합니다.

화면이 있는 앱은 빌드 성공에 더해 실제 주요 조작·읽기 쉬운 배치·오류 안내를 확인하는 기준을 둡니다. 브라우저 자동화나 실제 화면 검토 기록을 연결합니다. 사용자가 보지 않는 프레임워크 명칭과 검증 로그는 제품의 주 화면에 노출할 필요가 없습니다.

수정 영향이 작은 작업은 관련 검증으로 마칩니다. 프레임워크 검사나 전체 앱 검사는 변경의 영향 또는 명시된 배포 기준에 필요할 때 선택합니다. 실제로 실패한 부분을 고친 뒤 영향받는 검증을 다시 수행합니다.

examples/coding은 표준 라이브러리만 쓰는 숫자 변환 예시입니다. 실제 분자 모델링 과제의 완료 기준은 examples/molecular_modeling/REQUEST.md를 참고할 수 있습니다.
