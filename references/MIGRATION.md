# v3.1.1에서 이식하기

v4.0.0은 새 구조입니다. 이전 시스템 위에 덮어쓰지 말고 새 작업폴더에 풉니다. 기존 산출물·자료·테스트·의존성 명세를 필요한 범위만 옮깁니다. v3.1.1 원본 ZIP과 기존 결과는 보존합니다.

| v3.1.1 항목 | v4.0.0에서 처리 |
|---|---|
| INTENT | 실제 목적·제약을 새 INTENT.md로 요약 |
| SPEC | 복잡한 요구사항이면 유지; 필수 산출물 기준은 contract에 연결 |
| PLAN | 여러 의존 작업일 때 사용; 역할별 통과 절차는 이식하지 않음 |
| project_checks.json | source_paths와 검사 명령을 새 contract로 옮김 |
| Task Eval 20건 | 필요한 완료 기준별로 기존의 실제 검증을 연결 |
| state·checkpoint | 과거 기록으로 보존; 새 완료 증거로 재사용하지 않음 |
| .github 지침·hooks·Skills | 내용 감사 후 필요한 것만 재적용; 오래된 workflow_engine 명령은 제거/교체 |

기존 완성 앱에 아스트라 구조를 적용한 뒤에는 목적·계약을 작성하고 start → 실제 검증/검토 → finish로 새 근거를 만듭니다. 이전 PASS 숫자를 새 결과로 복사하지 않습니다.

모델은 실행 호스트에서 Astra를 선택합니다. 프로젝트 문서로 호스트의 모델·보안 정책을 덮어쓸 수 없습니다. 오래된 AGENTS.md와 새 지침을 함께 최상위 지침으로 사용하면 충돌할 수 있으므로 새 작업폴더에서 시작합니다.
