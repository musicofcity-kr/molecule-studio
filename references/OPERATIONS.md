# 실행과 복구

- start: 목적과 완료 계약의 형식 확인 후 working. 산출물은 아직 없어도 됩니다.
- verify: 실제 명령 실행과 내용 검토 확인. 통과하면 ready, 검토 대기는 working.
- finish: 최신 PASS 기록이 있으면 재사용하고 completed. 없거나 바뀌었으면 검증을 먼저 실행.
- status: 읽기 전용 상태와 증거 최신성. 앱 검사 명령을 실행하지 않음.
- start --new-run: 새 요청을 시작하고 이전 상태를 runs/history/에 보존. 기존 완료·검사 파일도 보존.

명령이 실패하면 코드를 수정해 다시 검사합니다. 기본적으로 동일한 소스와 같은 실패 기준이 두 번 반복되면 blocked가 됩니다. 이는 같은 조건에서 결과가 바뀌지 않는 재실행을 제한하며 모델의 전체 토큰·시간 예산을 제한하는 것은 아닙니다.

```bash
python tools/uaise.py resume --note "접근 문제를 해결했거나 다음 시도가 달라지는 근거"
```

실제 접근 권한·입력 자료가 필요한 경우에는 해결할 수 있는 작업까지 진행한 뒤 해당 장애물을 보고합니다. 사용량 대기나 권한 거부를 성공으로 바꾸지 않습니다.

검사는 명령별 시간과 총 시간 한도를 적용합니다. POSIX에서는 시간 초과 시 해당 명령의 프로세스 그룹을 종료합니다. Windows에서는 직접 실행한 프로세스를 종료하므로 손자 프로세스를 만드는 검사는 자체 정리 기능을 갖춰야 합니다. Windows 동작은 배포 검증 범위를 확인하세요.

runs/operation.lock은 두 상태 변경 명령의 동시 실행을 막습니다. 강제 종료 뒤 남은 잠금은 기록된 PID의 프로세스가 종료됐고 다른 작업도 실행 중이 아님을 확인한 후에만 제거합니다. 살아 있는 프로세스의 잠금을 자동 삭제하지 않습니다.

로그에는 프로젝트 명령의 출력이 저장됩니다. 비밀키·학생 식별정보를 출력하는 명령을 등록하지 않습니다. 이벤트 요약은 원문 프롬프트와 검토 본문을 저장하지 않습니다. 파일 해시는 백업·서명·보안 샌드박스를 대신하지 않습니다.
